结构化输出（Structured Output）

在 sampling 阶段引入约束解码，强制模型输出严格符合 JSON / JSON Schema。是 Function Call、API 编排、数据抽取等场景的「合规保险」。

为什么需要结构化输出

大模型自由生成 JSON 时常出错：键名拼错、引号丢失、嵌套不闭合、字段缺失。 下游系统拿到这种「半合法」的输出无法解析。

结构化输出在每一步采样时限制可选 token 集合，让模型只能选出符合 schema 的下一个 token。 不需要 prompt 工程，从机制上保证输出 100% 合法。

原理（基于 xgrammar / FSM）

  • 把 JSON Schema 编译成有限状态机（FSM）；
  • 每一步 sampling 时，结合当前 FSM 状态计算「合法 token 掩码」；
  • 把掩码 OR 进 logits（非法 token 设为 -∞），采样自然只命中合法 token；
  • FSM 状态根据采到的 token 转移。
   logits ─→ + mask(FSM, current_state) ─→ argmax / sampling ─→ token ─→ FSM transition ─→ ...
                                                                          │
                                                                  达到 accept 状态 → 终止

三种 response_format

type说明
text不约束（默认行为）
json_object必须输出合法 JSON 对象，但不校验具体字段
json_schema必须严格符合用户指定的 JSON Schema

请求示例（json_schema）

curl -H "Content-type: application/json" -X POST \
 -d '{
  "model": "dsv3_w8a8",
  "messages":[{"role":"user","content":"提取人员信息：李四，35 岁，产品经理，上海。"}],
  "response_format": {
    "type":"json_schema",
    "json_schema": {
      "name":"person_info",
      "schema": {
        "type":"object",
        "properties": {
          "name":      {"type":"string"},
          "age":       {"type":"integer"},
          "occupation":{"type":"string"},
          "city":      {"type":"string"}
        },
        "required":["name","age","occupation","city"]
      }
    }
  },
  "stream": false,
  "max_tokens": 256
 }' http://127.0.0.1:1025/v1/chat/completions

响应必然是合法 JSON：

{"name":"李四","age":35,"occupation":"产品经理","city":"上海"}

支持的 schema 关键字

遵循标准 JSON Schema：type（object / array / string / integer / number / boolean / null）、 properties、required、items、enum、 description、additionalProperties。

在 Python 框架中的实现

位于 mindie_llm/text_generator/plugins/structured_output/。 流程：

  1. 请求带 response_format → 自动加载结构化输出插件；
  2. plugin 在 sampling 前向 logits 注入 mask；
  3. plugin 在 token 生成后推进 FSM；
  4. FSM 抵达 accept 状态时主动结束生成（即使没到 max_tokens）。

已知限制

  • 支持 PD 混部、PD 分离场景。
  • 支持与 SplitFuse、Prefix Cache 叠加。
  • 不支持与 MTP、投机解码 叠加 （多 token 校验路径与 FSM 不兼容）。

收益

  • 下游解析失败率从 ~10% 降到 0。
  • 生成长度可控（FSM accept 后立即停），节省 token。
