安装与编译

MindIE-LLM 支持三种安装路径：官方镜像（推荐）、 软件包、源码自编。本章把仓库根目录的 build.sh 与 scripts/build_*.sh 一一拆解，方便定制构建。

三种安装方式对比

方式适用人群耗时注意事项
Docker 镜像新用户 / 生产分钟级预装全部依赖，最省心
软件包 .run裸机部署分钟级需先装好 CANN / ATB
源码编译二次开发20–60 min需 g++、cmake、Python 头文件等

方式一：Docker 镜像

从 昇腾镜像仓库 下载与卡型匹配的镜像（命名形如 mindie:<ver>-<arch>-py311-openeuler24.03-lts）。 启动命令见 快速入门。

镜像内组件路径：

  • CANN：/usr/local/Ascend/cann
  • ATB：/usr/local/Ascend/nnal/atb
  • MindIE：/usr/local/Ascend/mindie
  • ATB Models：/usr/local/Ascend/atb-models
  • MindIE-LLM Python：/usr/local/lib/python3.11/site-packages/mindie_llm

方式二：软件包安装

下载与硬件匹配的 Ascend-mindie-server_<ver>_linux-<arch>.run， 使用 scripts/install.sh 安装：

# 1. 安装 CANN 与 ATB（前置依赖）
# 2. 拷贝 .run 包到目标机器，加可执行权限
chmod u+x Ascend-mindie-server_*.run

# 3. 静默安装到默认目录
./Ascend-mindie-server_*.run --quiet --install
# 或调用仓库脚本：
bash scripts/install.sh

# 4. 设置环境变量（可加入 ~/.bashrc）
source /usr/local/Ascend/mindie/set_env.sh
source /usr/local/Ascend/cann/set_env.sh

卸载使用 scripts/uninstall.sh。升级时建议先重命名旧目录，避免动态库 解析到老版本（mv /usr/local/Ascend/mindie /usr/local/Ascend/mindie-bak）。

方式三：源码编译

3.1 依赖清单

依赖建议版本用途
CANN8.5.0底层运行时与算子库
ATB与 CANN 配套Transformer 融合算子
Python3.11Python 模块构建与运行
g++ / Clang≥ 9 / C++17编译 C++ 引擎
CMake≥ 3.20由根目录 CMakeLists.txt 驱动
Protobuf≥ 3.13编译 proto/
gRPC对应 protobuf 版本endpoint gRPC wrapper
Boost≥ 1.71HTTP / 工具库
OpenSSL≥ 1.1HTTPS / 加密

Python 端依赖见 requirements/ 与 requirements.txt，可用：

pip install -r requirements.txt

3.2 一键构建：build.sh

仓库根目录的 build.sh 是默认编译入口，内部串联了 scripts/ 下的 多个子脚本。常用调用：

# 全量构建（C++ + 第三方 + Python wheel + run 包）
bash build.sh

# 仅构建 C++ 引擎
bash build.sh src

# 仅打 run 包
bash build.sh run_package

3.3 子脚本职责

脚本作用典型产物
scripts/build_env.sh导出编译期环境变量（CANN 路径、Python ABI 等）—
scripts/build_third_party.sh编译 / 链接第三方依赖（gRPC、protobuf 等）third_party_entry/
scripts/build_kernels.sh构建昇腾自定义算子（src/kernels/）动态库
scripts/build_src.sh调用 CMake 编译 src/ 全部 C++ 模块libllm_*.so 等
scripts/build_dlt.sh构建数据 / 张量层（DLT），供 Python 与 C++ 共享动态库 + Python so
scripts/build_version_info.sh生成版本号头文件 / py 文件version.h 等
scripts/build_run_package.sh把上面所有产物打包成自解压 .runAscend-mindie-server_*.run
scripts/make_run_package.sh使用 makeself-header.sh 生成自解压头—
scripts/extract_debug_symbols.sh剥离 debug 符号生成 .dbg 文件*.dbg
scripts/get_cxx11_abi_flag.py探测当前 Python 的 C++11 ABI 标志stdout 标志

3.4 CMake 直接编译

若需要自行控制构建参数，可绕开 build.sh：

mkdir build && cd build
cmake .. \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/usr/local/Ascend/mindie \
  -DPYTHON_EXECUTABLE=$(which python3)
cmake --build . -j$(nproc)
cmake --install .

关键 CMake 选项可参见根目录 CMakeLists.txt 与 src/server/options.cmake。

3.5 Python wheel 安装

仓库提供两个 setup 入口：

  • setup_mindie_llm.py：构建 mindie_llm Python 包本身。
  • setup.py：构建包含 C++ so 的 wheel，最终用于发布。

典型流程：

# 开发模式（源码改动直接生效）
pip install -e .

# 构建 wheel
python setup.py bdist_wheel
ls dist/   # mindie_llm-*.whl

注意：pyproject.toml 约束了 build 系统与最低 Python 版本， 请保持环境一致。

环境变量速查

除 CANN / ATB 自身的 set_env.sh 之外，常用变量：

变量说明
MINDIE_LOG_TO_STDOUT=1 时把守护进程日志直接打印到 stdout，便于调试
MINDIE_LLM_LOG_LEVEL日志等级：DEBUG / INFO / WARN / ERROR
ASCEND_RT_VISIBLE_DEVICES限定本进程可见的 NPU 卡列表（影响逻辑 ID 编号）
HCCL_*多卡通信调优；多机推理需确保 ranktable 与 HCCL 一致
LD_LIBRARY_PATH需包含 CANN / ATB / MindIE 的 lib64 目录

验证安装

# Python 端能否 import
python -c "import mindie_llm; print(mindie_llm.__file__)"

# C++ 守护进程能否启动
mindie_llm_server --help

# 关键库是否可解析
ldd $(which mindie_llm_server) | grep -E 'mindie|atb|ascend'

若任一步报错，请回到 常见问题 查找解决方案。

卸载

# 软件包安装
bash scripts/uninstall.sh

# 源码安装
pip uninstall mindie_llm
rm -rf /usr/local/Ascend/mindie
