Python 推理框架

本章梳理 mindie_llm/ 主包的内部结构，包括请求接入 （connector）、推理工作流（text_generator）、模型抽象（modeling）、运行时（runtime）。

总览

                                  │
                         ┌────────┴───────┐

                         └────────┬───────┘
                                  ▼
                        ┌──────────────────┐

connector — 请求接入

路径 mindie_llm/connector/

  • main.py：进程入口，负责创建事件循环、启动 listener。
  • request_listener/：监听来自 C++ Server 的请求消息， 解码到 Python dict / dataclass。
  • request_router/：把请求按 modelName / lora_id 路由到对应的 text_generator 实例。
  • cpp/：与 C++ 桥接的 binding 代码，复用 src/llm_manager/python_api 的 pybind11 接口。
  • common/：通用数据结构与异常定义。

text_generator — 推理工作流

路径 mindie_llm/text_generator/

核心类 Generator

文件 generator.py。整个 Python 推理的入口。它持有：

  • ModelRunner — 执行 forward。
  • Sampler — 采样下一个 token。
  • PluginManager — 加载 / 调度插件。
  • MemPool — 张量复用池。

主循环近似：

def step(batch):
    plugin_manager.before_forward(batch)
    inputs = preprocess(batch)
    outputs = model_runner.forward(inputs)
    next_tokens = sampler.sample(outputs, batch.params)
    plugin_manager.after_forward(batch, next_tokens)
    return postprocess(batch, next_tokens)

adapter / samplers / mempool / utils

  • adapter/：兼容多种调度协议（OpenAI / Triton）的请求适配。
  • samplers/：温度、top-k、top-p、repetition_penalty、 beam search、典型 p 采样、greedy、structured constrained sampling 等。
  • mempool/：tensor cache，避免反复 torch.empty。
  • utils/：tokens helper、stop checker、profiling 钩子。
  • cpp/：性能敏感路径的 C++ 加速实现（如批量 token 校验）。

plugins/ — 高阶特性插件

路径 mindie_llm/text_generator/plugins/。每个插件是一个独立子模块， 实现 Plugin 抽象类，由 plugin_manager.py 管理生命周期。

插件作用对应特性
prefix_cachePrefill 命中前缀复用 KV Prefix Cache
splitfuse长 prefill 切块与 decode 融合 SplitFuse
memory_decoding基于历史 KV 加速解码 Memory Decoding
laLookahead Decoding 并行解码
mtpMulti-Token Prediction MTP
structured_outputJSON / 正则约束输出 Structured Output
layer_skipped跳层推理 Layer Skipped

plugin_manager_lwd.py 是 LayerwiseDecode 专用的 plugin 调度器， 插件可挂在 layer 粒度的钩子上。

modeling — 模型抽象

路径 mindie_llm/modeling/

  • backend_type.py：枚举 ATB / ACL / Eager 等后端。
  • model_wrapper/atb/：把 ATB Models 中的实现包装成 统一的 forward(input_ids, kv_cache, ...) 接口。

更多模型实现位于 examples/atb_models/，由 modeling 包动态加载。

runtime — 运行时

路径 mindie_llm/runtime/。这是「真正算」的地方，组件众多：

model_runner / models / compilation

  • model_runner/：负责加载权重、构造模型、维护 KV 句柄； 提供 warmup / forward / capture_graph 等接口。
  • models/：内置模型目录，供 model_runner 实例化。
  • compilation/：图编译路径
    • ACLGraph：基于 CANN 的图捕获，跑 stream-capture。
    • ATBGraph：基于 ATB Models 的高度融合图，需匹配 ATB 后端。

layers/ — 通用模型模块

路径 mindie_llm/runtime/layers/。提供：

  • attention — Self-Attention / MLA 等。
  • embedding — Token / Position / Rope 嵌入。
  • linear — ColumnParallelLinear / RowParallelLinear / LoRA-aware Linear。
  • fused_moe — MoE 融合算子，含 routing、permute、合并。
  • quantization — 各量化层（W8A8、W4A8、KV Int8 等）。
  • sampling — 采样算子（temperature、top-k 等）的 device 端实现。
  • normalization.py — RMSNorm / LayerNorm。
  • parameter.py — 参数封装。
  • custom_layer.py — 用户自定义层抽象基类。

ops/ — 算子

路径 mindie_llm/runtime/ops/。包括：

  • fla — Fused LLM Attention 等。
  • triton — 基于 Triton 的算子内核（昇腾 Triton 后端）。
  • mie_ops — MindIE 自研算子。

lora / tokenizer / config / utils

  • lora/：Adapter 加载、合并、激活。
  • tokenizer/：fast tokenizer 包装 + 缓存。
  • config/：模型 / 推理 / 后端 / 量化的运行时配置类。
  • conf/：默认配置 JSON。
  • utils/：日志、张量、profiling、校验。

distributed/ — 分布式

路径 mindie_llm/distributed/。封装通信组创建：

  • 张量并行通信组（TP group）
  • 数据并行通信组（DP group）
  • 专家并行通信组（EP group）
  • 上下文并行 / 序列并行的子组

所有 group 由 config_manager/ranktable_config.cpp 解析后传入， Python 端通过 HCCL / Gloo 等后端建立。

server/main.py — 独立 Python 入口

提供一个轻量级 Python 启动器，跳过 C++ daemon 直接拉起推理服务，便于调试。 生产环境推荐用 mindie_llm_server。

Python ↔ C++ 桥

整个 Python 框架与 C++ 引擎通过 pybind11 + protobuf 双通道通信：

  • 控制面：src/llm_manager/python_api/ 暴露 add_request / step / get_results 等同步调用。
  • 数据面：src/py_interface/ 提供 tensor / block table / sampling 参数的零拷贝交换。
  • 消息面：proto/model_execute_data.proto 定义跨进程消息（IPC / gRPC 通用）。

开发提示

  • 新增 plugin → 继承 plugins/plugin.py 的接口；在 plugin_manager.py 注册；通过 config.json → ModelConfig.pluginParams 启用。
  • 新增 layer → 放在 runtime/layers/；在 custom_layer.py 或具体模型中调用。
  • 新增 sampling → text_generator/samplers/ 添加并通过参数 dispatch。
  • 性能瓶颈在 host → 把热点搬到 text_generator/cpp/ 用 C++ 重写。
