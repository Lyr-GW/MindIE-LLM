项目简介

MindIE-LLM 是华为昇腾针对大语言模型推理场景打造的一套高性能推理引擎， 旨在为千亿级稠密 / 万亿级 MoE 模型提供生产可用的服务化能力。

定位与目标用户

在「训练 → 微调 → 推理 → 服务化」整条 LLM 工程链路中，MindIE-LLM 聚焦在 推理与服务化这一段。它的核心目标是：

  • 在昇腾硬件上把模型跑出与同代 GPU 推理引擎可比甚至更优的 TPS / TTFT / TPOT。
  • 对接现有生态。不让用户重写客户端 — 你的 OpenAI / vLLM / TGI / Triton 客户端代码几乎可以零改动指向 MindIE-LLM 服务。
  • 给 MoE / 长序列 / 量化等前沿场景提供「开箱即用」实现， 而不是把 hacky 的研究代码留给用户去拼。

典型用户群体包括：

  • 使用昇腾服务器搭建 LLM 在线推理服务的云服务 / 大模型应用厂商。
  • 需要把开源模型从 GPU 平滑迁移到昇腾的研究与工程团队。
  • 希望定制调度策略 / 量化 / 并行方案的资深推理工程师。

在 MindIE 全家桶中的位置

MindIE 是华为昇腾的统一推理引擎品牌，按业务域拆成若干子组件。MindIE-LLM 是其中 面向「大语言模型」场景的子组件，与同生态内的其他组件协同工作：

   │                  应用层 / 客户端                       │
   │   OpenAI SDK · vLLM client · TGI · Triton · curl      │

                            │  HTTP / gRPC
                            ▼
   ┌─────────────────────────────────────────────────────────┐

                            │  内部 gRPC / IPC
                            ▼
   ┌─────────────────────────────────────────────────────────┐
   │                ▶▶  MindIE-LLM  ◀◀                       │

关键关系：

  • CANN 提供驱动 / Runtime / 算子编译，是底座。
  • ATB（Ascend Transformer Boost）/ ATB Models 提供面向 Transformer 的 高性能融合算子与典型模型实现，被 MindIE-LLM 通过 examples/atb_models 与 mindie_llm/modeling/model_wrapper/atb 集成。
  • ACLNN / ACLGraph 是另一条算子 / 图通道，MindIE-LLM 也支持 ACLGraph 后端（详见 架构总览）。
  • MindIE-Service 是更上层的统一服务化网关，可以把多个 MindIE-LLM 实例 组成集群对外提供服务。本仓库聚焦 LLM 引擎本身，不包含 Service 层。

核心能力速览

高吞吐服务化
Continuous Batching、PagedAttention、FlashDecoding 默认开启；SplitFuse 把长 Prefill 切块塞入空闲 Decode 步，提升整体利用率。
多协议接入
单进程同时暴露 OpenAI / Triton / TGI / vLLM 风格 API， 外加自研原生接口 /infer / /infer_token。
多并行方案
TP / DP / EP / CP / SP 自由组合，ranktable 描述多机多卡拓扑。
主流量化齐备
权重 / 激活 / KV Cache 三个维度都有量化方案；W8A8、W4A8、 KV Int8、Attention 量化等可叠加使用。
前沿特性插件化
Prefix Cache、MTP、Lookahead Decoding、Memory Decoding、 Structured Output 等通过 plugins/ 机制热插拔。
PD 分离与池化
Prefill / Decode 实例可独立伸缩；KV Cache 池化把 DRAM、SSD 纳入二级缓存，命中率显著提升。

硬件支持

MindIE-LLM 目前主要面向以下硬件形态：

产品形态典型用途
Atlas 800I A2 推理服务器单机 8 卡主流 7B–70B 模型推理
Atlas 800I A3 超节点多机互联超节点千亿稠密 / 万亿 MoE
Atlas 训练系列训练集群训练后的就地推理验证
📌 NPU 设备命名

容器内通过 /dev/davinci{0..7} 表示 8 张物理卡， npu-smi info 可查看占用与逻辑 ID。MindIE-LLM 在 config.json → BackendConfig.npuDeviceIds 中以二维数组表达 「实例 → 卡集合」的映射。

版本与发布

当前主分支对应 MindIE 2.3.0，匹配 CANN 8.5.0。 版本节奏与昇腾整体发布保持一致，详见仓库根目录 docs/zh/release_notes.md。重要里程碑：

  • 2025/12 项目正式开源，面向公众开放贡献。
  • 2026/04 在线文档站上线，提供完整中文使用 / 开发指南。

范围与非目标

为帮助用户准确选型，明确 MindIE-LLM 不做什么：

  • 不做模型训练 / 微调。训练能力由 MindSpeed / MindFormers 等组件承担。
  • 不做向量检索 / RAG 编排。这些属于业务层，可在前置网关或应用代码中实现。
  • 不做多模态生成（图像 / 视频）。专注 LLM 文本推理；多模态理解 类模型（图文理解、ASR 后端 LLM 等）通过迁移指南支持。
