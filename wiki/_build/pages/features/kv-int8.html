KV Cache Int8

仅对 K Cache 与 V Cache 做 INT8 量化，权重 / 激活 不动。在长序列、显存受限场景里，是「投入产出比最高」的量化项之一。

解决什么问题

大模型 decode 阶段，KV Cache 占用通常远超模型权重本身。例如 LLaMA3-70B、序列 4k， 单请求 KV ≈ 4 GB；并发 200 个请求时，KV 总量 ≈ 800 GB —— 单凭显存的 maxBatchSize 直接被 拖死。

把 KV 压到 int8（fp16 → int8）体积立刻 1/2，maxBatchSize 可上调一档，吞吐显著提升。

原理

// KV 写入时（每生成 1 个 token）
k_int8 = round((k_fp16 - kv_cache_offset) / kv_cache_scale)
v_int8 = round((v_fp16 - kv_cache_offset) / kv_cache_scale)

// PagedAttention 读出时
k_fp16 = k_int8 * kv_dequant_scale + kv_dequant_offset
v_fp16 = v_int8 * kv_dequant_scale + kv_dequant_offset

scale / offset 在权重侧通过校准数据集离线学到，存在 k_proj.kv_cache_scale、k_proj.kv_cache_offset 等张量中。 推理时由 ATB 算子内部派生出 k_quant_scale、k_dequant_scale、 v_quant_scale、v_dequant_scale 等具体常数。

权重描述

{
  "model_quant_type": "W8A8",
  "kv_cache_type":    "C8",                                 // ← 表示 KV Cache int8
  "model.layers.0.self_attn.q_proj.weight": "FLOAT",        // q 不量化
  "model.layers.0.self_attn.k_proj.weight": "FLOAT",
  "model.layers.0.self_attn.k_proj.kv_cache_scale":  "W8A8",
  "model.layers.0.self_attn.k_proj.kv_cache_offset": "W8A8",
  "model.layers.0.self_attn.v_proj.weight": "FLOAT",
  "model.layers.0.self_attn.v_proj.kv_cache_scale":  "W8A8",
  "model.layers.0.self_attn.v_proj.kv_cache_offset": "W8A8"
}
张量dtypeshape
kv_cache_scalefp16[kv_head_num × head_dim]
kv_cache_offsetfp16[kv_head_num × head_dim]

如何开启

需要带 KV Cache Int8 校准的量化权重，msModelSlim 有专门开关：

msmodelslim quant \
  --model_path /home/llama3-70b \
  --save_path  /home/llama3-70b-w8a8-c8 \
  --device     npu \
  --model_type LLaMA3-70B \
  --quant_type w8a8 \
  --kv_cache_int8  \
  --trust_remote_code True

启动时引擎自动识别 "kv_cache_type": "C8"。

收益

  • KV 显存 1/2 → maxBatchSize 翻倍 → 总吞吐 1.4–1.8×（业务依赖）。
  • 解码阶段 attention 算子可走 KV-int8 优化路径，单步时延也略降。
  • 精度损失通常 < 0.5 pp。

已知限制

  • 仅 Atlas 800I A2 推理服务器支持。
  • 必须搭配 W8A8。
  • 仅支持 LLaMA3.1-70B、Qwen2-72B、Qwen2.5-72B-Instruct 等。
  • 仅支持 fp16。
  • 与 W4A8 混合量化 不兼容。

调优建议

  • 开启后请评估 P99 输出质量；KV 量化误差会随 decode 长度累积。
  • 对极长上下文（> 32k），优先选 FA3 量化。
  • 命中 Prefix Cache 的请求会复用量化前的 KV，要确保 prefix 与新 token 的量化 scale 一致 — MindIE-LLM 已在算子内部统一处理。
