Function Call（工具调用）

让大模型能调用外部函数 / API，把推理与「搜索、计算、数据库」等 工具能力打通。是 LLM 应用走向「代理（agent）」的关键一步。

整体流程

   ① 应用 → 模型：system prompt + 用户输入 + 可用工具集合
   ② 模型决策：直接答 / 选 1 个或多个工具 → 返回 tool_calls JSON
   ③ 应用解析 tool_calls，本地执行工具，得结果
   ④ 应用 → 模型：把工具结果作为 tool 角色发回
   ⑤ 模型综合工具结果生成最终答案

配置

"ModelConfig": [{
  "modelName":       "dsv31",
  "modelWeightPath": "/data/weight/DeepSeek-V3.1",
  "worldSize":       16,
  "models": {
    "deepseekv2": {
      "tool_call_options": { "tool_call_parser": "deepseek_v31" },
      "chat_template":     "/path/to/tool_chat_template_deepseekv31.jinja"
    }
  }
}]

关键参数：

  • tool_call_parser：选择对应模型的工具解析模块（DeepSeek-V3.1 必须填 deepseek_v31，其余模型可缺省由引擎自动匹配）。
  • chat_template：自定义 jinja 对话模板。DeepSeek 默认 chat_template 不支持工具调用，需用专门的 tool 模板替换。

请求示例

curl -X POST https://127.0.0.1:1025/v1/chat/completions \
 -H "Content-Type: application/json" -d '{
  "model": "dsv31",
  "messages": [{"role":"user","content":"帮我查 999888 这个订单什么时候送到？"}],
  "tools": [{
    "type":"function",
    "function": {
      "name":"get_delivery_date",
      "description":"查询订单送达日期",
      "parameters": {
        "type":"object",
        "properties": {"order_id":{"type":"string"}},
        "required":["order_id"]
      }
    }
  }],
  "tool_choice":"auto",
  "stream": false
}'

响应中的 tool_calls：

"tool_calls": [{
  "id":"call_JwmTNF3O",
  "type":"function",
  "function": {
    "name":"get_delivery_date",
    "arguments":"{\"order_id\":\"999888\"}"
  }
}]

应用执行工具，把结果以 role: tool 发回模型，得最终答案。

已知限制

  • Atlas 800I A2 / A3、Atlas 300I Duo 支持。
  • 仅 OpenAI chat 接口。
  • 支持模型：ChatGLM3-6B、Qwen3 系列、DeepSeek-R1-0528、Qwen2.5-Instruct、DeepSeek-V3.1。
  • 支持与量化、长序列、多机、PD 分离、MoE、Multi-LoRA、SplitFuse、并行解码、EP、MTP、 Prefix Cache、思考解析*、TP、MLA 叠加。
  • SplitFuse / 并行解码 / MTP 不支持流式下叠加 Function Call。
  • 仅 Qwen3 系列、DeepSeek-R1-0528 支持流式 Function Call。
  • 不支持：include_stop_str_in_output、stop、best_of、 n、use_beam_search、logprobs。
  • JSON 嵌套层数 ≤ 10。
  • DeepSeek-V3.1 一条请求不能同时使能 Function Call 与思考解析。
