--- title: MoE 模型支持 ---

MoE（Mixture of Experts）

把单一 FFN 替换为 N 个并行的「专家」，每个 token 只激活其中 K 个 — 在不显著增加单 token 计算量的前提下，把模型容量推向万亿级别。

这是什么

传统 Transformer 在每个 block 内是 Attention → FFN。MoE 把 FFN 改为：

x ──→ Router (gate) ──→ topK 选择 K 个专家 ──→ 加权求和 ──→ y
              │                              │
              └─ K 远小于 N（例如 N=8, K=2） ─┘

每个 token 只「点亮」少量专家，但所有专家都驻留显存 → 容量 ↑、单 token 算力大致不变。

两个关键机制

  • Sparse MoE Layer：替换原 FFN，N 个专家并行存在。
  • Router：通常是一层 Linear + softmax，决定 token 去哪 K 个专家。 如何避免专家失衡是核心难点（详见 EPLB）。

支持模型与并行能力

模型数据格式量化并行多机
Mixtral 8×7BFP16暂不支持TP否
Mixtral 8×22BFP16暂不支持TP否
DeepSeek-16B-MoEFP16暂不支持TP否
DeepSeek-V2 / V3 / R1BF16支持TP / EP是
Qwen3-30B-A3BBF16支持TP否
Qwen3-235B-A22BBF16支持TP是

引擎内部

  • Python 层：mindie_llm/runtime/layers/fused_moe/ 实现 routing、permute、grouped matmul、reduce 全流程的融合算子。
  • 专家并行：见 Expert Parallel。
  • 负载均衡：见 EPLB。
  • 共享专家外置：见 共享专家外置。

如何开启

没有「开关」 — 选用 MoE 模型即自动启用。直接把模型权重路径写入 config.json 即可：

"ModelConfig": [{
  "modelName":       "deepseekr1",
  "modelWeightPath": "/weights/DeepSeek-R1",
  "worldSize":       16,
  "tp": 8, "moe_ep": 4, "moe_tp": 2
}]

为什么 MoE 跑得动

同等参数量下：

  • 稠密模型：所有参数对每个 token 都做计算。
  • MoE 模型：每 token 只激活 K/N 比例（如 1/4）的参数 → 单 token 算力低 ~4×。

但 MoE 把带宽与负载均衡变成新瓶颈，需要 EP / EPLB 协作解决。

Grouped MatMul 自动融合

当 EP 数 > 32 时，DeepSeek-V3 / R1 自动启用 Grouped MatMul 融合算子， 把同一卡上多个专家的 matmul 合并下发，降低 kernel launch 开销。
