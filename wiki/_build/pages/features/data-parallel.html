--- title: Data Parallel ---

Data Parallel（数据并行）

把请求分配到不同设备组并行处理，结果合并。等价于「同一模型部署多份实例」， 推理阶段几乎无组间通信，是横向扩并发最简单的并行方式。

什么时候用 DP

  • 显存够装一份模型，但 QPS 没顶到上限 — DP 直接线性扩并发。
  • MoE 模型的 Attention 部分（计算密集、通信少）适合 DP；MoE 部分仍走 TP / EP。
  • 多实例不需要共享上下文（不同业务、不同租户）。

原理

每个 DP 实例独立持有一份完整模型副本，独立维护自己的 KV Cache 与 batch。 请求路由层（如 endpoint + load balance）负责把请求分发给 合适的实例。

   Request 1 ──→ DP-Inst-0 (NPU 0,1,2,3)  ──→ Response 1
   Request 2 ──→ DP-Inst-1 (NPU 4,5,6,7)  ──→ Response 2
   Request 3 ──→ DP-Inst-0 (NPU 0,1,2,3)  ──→ Response 3
   ...

配置字段

在 ModelConfig 下加 tp / dp / cp / sp：

字段含义约束
tp整网张量并行数tp × dp = worldSize（与 cp/sp 联动）
dpAttention 数据并行数−1 表示关闭，默认 −1
cp上下文并行数1 = 关闭；与 sp 配合时 dp=1
sp序列并行数与 tp 配合时 sp=tp

配置示例

8 卡：Attention 走 DP=8、MoE 走 TP=1（或者 MoE 由 moe_tp 控制）：

"ModelConfig": [{
  "modelName": "deepseekv2",
  "modelWeightPath": "/weights/DeepSeek-V2-Chat-W8A8-BF16/",
  "worldSize": 8,
  "tp": 1,
  "dp": 8,
  "cp": 1,
  "sp": 1
}]

多实例（DP=2）+ TP=4：

"BackendConfig": {
  "npuDeviceIds": [[0,1,2,3], [4,5,6,7]],
  ...
  "ModelConfig": [{
    "modelName": "qwen2-72b",
    "modelWeightPath": "/weights/qwen2-72b",
    "worldSize": 4
  }]
}

注意：实例级的 DP 通过 npuDeviceIds 二维数组表达； 模块级的 DP（仅 Attention 走 DP）则通过 tp/dp 字段表达。

环境变量优化

export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export ATB_WORKSPACE_MEM_ALLOC_ALG_TYPE=3

收益

  • 多实例 DP：吞吐近线性扩展，QPS 受总卡数 / 单实例 batch 上限决定。
  • 模块级 DP（仅 Attention）：避免长上下文场景下 attention TP 通信过重。

已知限制

  • Atlas 800I A2 / A3 支持。
  • 所有模型的 Attention / MLP 模块均支持。
  • DP 与 TP 可在同一模块上叠加使用（详见 tp×dp=worldSize 公式）。
