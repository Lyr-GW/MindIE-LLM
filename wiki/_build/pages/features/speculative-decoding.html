并行解码 — Speculative Decoding / Lookahead / Memory Decoding

用「先猜 N 个 token、再用主模型一次性校验」的方式，把多步 decode 压缩成一次 forward。本特性是访存受限场景的吞吐利器。

动机

Decode 阶段每步只算 1 个 token，每步都要把整个权重从 HBM 读一遍 — 计算资源大量空闲、 访存带宽 100% 占用。如果一次 forward 同时验证 N 个候选 token，就能在同样访存 下输出 N 个 token。

两种算法（互斥）

算法候选 token 来源适用场景
memory_decoding前缀树（Trie）缓存历史输入输出代码生成 / 检索类（重复 pattern 多）
lookahead (la)Jacobi 迭代 + prompt + 输出结果文本生成 / 对话 / 多样化问答

memory_decoding

"speculationGamma": 16,
"ModelConfig": [{
  "plugin_params":"{\"plugin_type\":\"memory_decoding\",\
                    \"decoding_length\":16,\"dynamic_algo\":true}",
  "modelName": "llama3-70b",
  ...
}]
  • decoding_length ∈ [1,16]：候选最大长度。
  • dynamic_algo=true：根据上下文自适应候选长度。
  • speculationGamma ≥ decoding_length。
  • 当 dynamic_algo=true，maxIterTimes ≥ 期望输出长度 + speculationGamma。

lookahead (la)

"speculationGamma": 30,
"ModelConfig": [{
  "plugin_params":"{\"plugin_type\":\"la\",\"level\":4,\"window\":5,\"guess_set_size\":5}",
  "modelName": "Qwen2.5-7B-Instruct",
  ...
}]

Lookahead 用 Jacobi 迭代直接从主模型自身的 N-gram 缓存生成候选；不需要额外 draft 模型。

  • level (N) / window (W) / guess_set_size (G) ∈ [1,16]，默认 4 / 5 / 5。
  • speculationGamma ≥ (N-1) × (W+G)，建议取等。

何时收益最大

  1. 并发较低（内存带宽受限）；
  2. 有较长输入提供候选 token 来源；
  3. 有较长输出（推理步数足够多）；
  4. 贪婪 / 低温度采样（验证通过率高）。

在 Python 框架中的实现

位于 mindie_llm/text_generator/plugins/：

  • plugins/la/：lookahead 实现。
  • plugins/memory_decoding/：memory decoding 实现。

调度器侧把每个 step 的 numBatchedTokens 设为 1 + N， 模型 forward 一次同时算 N+1 个 token；后处理层根据校验通过的 token 数推进序列。

已知限制

  • Atlas 800I A2、Atlas 300I Duo 支持。
  • LLaMA3、Qwen2 / 2.5、Qwen3-14B / 32B 支持。
  • 支持 W8A8 与稀疏量化；其它量化暂不支持。
  • 不能与 PD 分离、Multi-LoRA、 SplitFuse、长序列、MTP、 异步调度、多机推理同开。
  • 不支持 n / best_of / use_beam_search / logprobs / top_logprobs 等。
  • 暂不支持流式推理。
  • 惩罚后处理仅支持 repetition_penalty。
  • 暂不支持开启 HealthCheck。
  • la 与 memory_decoding 不可同时使能。
