--- title: Micro Batch ---

Micro Batch（双流掩盖）

把一个 batch 切成两个 micro batch 在两条 NPU 数据流上交替执行， 让计算与通信同时进行，硬件资源充分利用。

动机

Prefill 阶段经常出现「计算算子算 → 集合通信通 → 计算算子算 → ...」的串行流水。 通信类算子（AllReduce、AllToAll）耗时长，与计算算子互相不冲突。 用两条 stream 交替推进两个 micro batch，可以做到「一边在算、一边在通」。

   单流 baseline：
   stream0:  [calc0]→[comm0]→[calc1]→[comm1]→[calc2]→[comm2]→...

   Micro Batch 双流：
   stream0:  [calc0a] [comm0a] [calc1a] [comm1a] [calc2a] [comm2a]
   stream1:           [calc0b] [comm0b] [calc1b] [comm1b] [calc2b]
                       ↑↑           ↑↑          ↑↑
                       重叠         重叠        重叠

同步机制

两条数据流通过 NPU Event 实现细粒度同步：

  • 计算 / 通信任务互相不冲突，避免硬件资源抢占；
  • 每个 micro batch 完成关键节点（如 layer 边界）触发 Event；
  • 对端 stream 等到 Event 后再开始下一段。

在 Prefill 阶段计算 / 通信耗时占比相对均衡，掩盖率达 70%+。

配置

"ModelConfig": [{
  "modelName":       "Qwen3-14B",
  "modelWeightPath": "/data/weights/Qwen3-14B",
  "worldSize":       8,
  "models": {
    "qwen3": {
      "ccl": { "enable_mc2": false },          // 关闭通信计算融合算子
      "stream_options": { "micro_batch": true } // 开启 Micro Batch
    }
  }
}]

代价

  • 多了一条数据流和重复 buffer，额外占用一些显存。
  • 服务化场景下 KV Cache 数量减少，可能让 maxBatchSize 调度受限。
  • 显存紧张场景慎用。

已知限制

  • 不默认开启。
  • 不能与通信计算融合算子（mc2）特性同时开启。
  • 仅 Qwen2.5、Qwen3 稠密、DeepSeek-R1、DeepSeek-V3.1 支持。
  • Qwen 模型上可与并行解码、 异步调度、SplitFuse、 Prefix Cache 同开。
  • DeepSeek 模型上可与 MTP 同开。

收益

  • Prefill 阶段时延降低 20–40%（视通信比重）。
  • 对长上下文 prefill 尤其明显。
