--- title: 权重离线切分 ---

权重离线切分

把按运行时并行策略切分好的权重提前落盘到 tmpfs， 启动时只做拷贝。可显著缩短 DeepSeek 这类巨型模型的冷启动时间，从分钟级降到秒级。

默认加载流程的开销

   safetensors (磁盘) → 完整加载到 host 内存 → 按 TP/EP 切分 → H2D 拷贝到 NPU
                ↑                  ↑               ↑           ↑
              I/O 密集          内存复制      串行计算       PCIe / HCCS 带宽

对 DeepSeek-V3 / R1（700+ GB），此流程要分钟级，扩容 / 升级体验差。

离线切分思路

   离线（一次性）：
   完整 safetensors → 按 dp / tp / moe_tp / moe_ep 预切分 → 写入 tmpfs

   在线（每次启动）：
   tmpfs → 直接 mmap 到 host → H2D → NPU
   省去：完整加载 / 切分 / 内存复制

tmpfs 是基于内存的文件系统，访问开销近于直接内存读写。

权重切分命令

Atlas 800I A3 单机（16 卡）

# 如果在线场景使能 MTP，先设置环境变量
export DEEPSEEK_MTP=1

torchrun --nproc_per_node 16 --master_port 20030 \
  -m examples.convert.weight_sharder \
  --model_path     /weights/DeepSeek-R1 \
  --dp 2 --tp 8 --moe_tp 4 --moe_ep 4 \
  --save_directory /tmpfs/DeepSeek-R1-sharded

Atlas 800I A2 双机（每机 8 卡）

export DEEPSEEK_MTP=1
export RANK_TABLE_FILE=/path/to/ranktable.json

# 主节点
torchrun --nnodes=2 --nproc_per_node 8 --node_rank=0 \
  --master_addr=<主节点 IP> --master_port 20030 \
  -m examples.convert.weight_sharder \
  --model_path /weights/DeepSeek-R1 \
  --dp 2 --tp 8 --moe_tp 4 --moe_ep 4 \
  --save_directory /tmpfs/DeepSeek-R1-sharded

# 从节点
torchrun --nnodes=2 --nproc_per_node 8 --node_rank=1 \
  --master_addr=<主节点 IP> --master_port 20030 \
  -m examples.convert.weight_sharder ... 同上

切分后目录结构

├── config.json
├── model-000 ... model-015          # 16 份 attention / dense 切分
├── model-attn-tp-000 ... 007        # 8 份 attention TP
├── model-dense-tp-000 ... 007       # 8 份 dense TP
├── model-moe-tp-000-ep-000 ... 003-003   # 16 份 MoE TP×EP
├── model-norm
├── model_sharded_metadata.json      # 索引切分策略与文件
├── quant_model_description_w8a8_dynamic.json
├── tokenizer.json
└── tokenizer_config.json

启用

把 modelWeightPath 直接指向切分后的 tmpfs 目录即可：

"ModelConfig": [{
  "modelName":       "DeepSeek-R1_w8a8",
  "modelWeightPath": "/tmpfs/DeepSeek-R1-sharded",
  "worldSize":       16
}]

引擎检测到 model_sharded_metadata.json 即自动走预切分路径。

收益

  • DeepSeek-R1 单机 16 卡冷启动从 ~3 min 降到 < 30 s。
  • 大幅缩短发布 / 扩容窗口期。

已知限制

  • 仅 DeepSeek-R1、DeepSeek-V3 支持。
  • 切分时配置必须与运行时完全一致（dp / tp / moe_tp / moe_ep）。
  • 仅 Atlas 800I A2 双机、Atlas 800I A3 单机支持。
  • 不支持与共享专家和路由专家合并同开。
  • 不支持与动态负载均衡同开。
  • tmpfs 必须留足空间（按权重总体积 + 一份元数据）。
