快速入门

本章用 Atlas 800I A2 + Qwen2-7B 作为示例， 在 10 分钟内完成「拉镜像 → 启动容器 → 配置模型 → 启动服务 → 发请求」全流程， 并简要演示 AISBench 精度 / 性能测试入口。

🎯 这一章你将得到

一个跑在昇腾上的、对外提供 POST /generate 接口的 Qwen2-7B 推理服务， 以及验证它精度与性能的命令模板。

环境前置检查

在执行后续步骤前，确认宿主机上已经具备：

  1. NPU 驱动 / 固件：执行 npu-smi info 能正常返回卡列表。 
    npu-smi info
    若命令不存在或报错，请先按《Atlas A2 中心推理和训练硬件 NPU 驱动和固件安装指南》物理机章节安装。
  2. Docker：能成功执行 docker ps。
  3. 有可访问的模型权重目录，例如 /home/weight，里面存放 Qwen2-7B 的 config.json + *.safetensors 等。

第一步：准备权重

从 HuggingFace 下载 Qwen2-7B：

# 任选一种下载方式
git lfs install
git clone https://huggingface.co/Qwen/Qwen2-7B /home/weight

# 修正权限（MindIE 对权重目录有 755 / 文件 640 的硬性要求）
chmod -R 755 /home/weight

第二步：拉取并启动 MindIE 镜像

登录 昇腾镜像仓库， 根据卡型选择 800I-A2 镜像。容器内已预装 CANN、ATB、ATB-Models、MindIE-LLM。

docker run -it -d --net=host --shm-size=1g \
  --name mindie-llm-demo \
  -w /home \
  --device=/dev/davinci0:rwm \
  --device=/dev/davinci1:rwm \
  --device=/dev/davinci2:rwm \
  --device=/dev/davinci3:rwm \
  --device=/dev/davinci_manager:rwm \
  --device=/dev/hisi_hdc:rwm \
  --device=/dev/devmm_svm:rwm \
  -v /usr/local/Ascend/driver:/usr/local/Ascend/driver:ro \
  -v /usr/local/dcmi:/usr/local/dcmi:ro \
  -v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi:ro \
  -v /usr/local/sbin:/usr/local/sbin:ro \
  -v /home/weight:/home/weight:ro \
  mindie:2.2.RC1-800I-A2-py311-openeuler24.03-lts bash

docker exec -it mindie-llm-demo /bin/bash
⚠ 关于 --device 权限

挂载 NPU 设备时务必使用 rwm。设置为更小权限（如 rw）会 在该卡被其它任务占用时导致 npu-smi 报错且 torch.npu.set_device() 失败 — 这是迁移用户最常踩的坑之一。

容器内目录速查

组件容器内路径
CANN/usr/local/Ascend/cann
CANN-NNAL-ATB/usr/local/Ascend/nnal/atb
MindIE/usr/local/Ascend/mindie
ATB Models/usr/local/Ascend/atb-models
MindIE-LLM Python 包/usr/local/lib/python3.11/site-packages/mindie_llm

第三步：编辑 config.json

找到 Python 包安装位置，进入 conf 目录修改：

SP=$(pip show mindie_llm | awk '/Location:/{print $2}')
cd $SP/mindie_llm/conf
chmod 640 config.json     # 必须 640，否则启动失败
vim config.json

典型最小修改如下（其余字段保留默认即可）：

{
  "ServerConfig": {
    "httpsEnabled": false
  },
  "BackendConfig": {
    "npuDeviceIds": [[0, 1, 2, 3]],
    "ModelDeployConfig": {
      "ModelConfig": [
        {
          "modelName": "qwen2-7b",
          "modelWeightPath": "/home/weight",
          "worldSize": 4,
          "trustRemoteCode": false
        }
      ]
    }
  }
}
字段含义典型取值
httpsEnabled是否开启 HTTPS生产建议 true
npuDeviceIds每实例使用的 NPU 卡集合[[0,1,2,3]]
modelName对外暴露的模型名qwen2-7b
modelWeightPath权重目录（容器内绝对路径）/home/weight
worldSize张量并行卡数需与 npuDeviceIds 集合大小一致
trustRemoteCode是否执行权重目录里的远程代码默认 false

第四步：启动服务

export MINDIE_LOG_TO_STDOUT=1   # 让日志直接打印到当前终端
mindie_llm_server

看到 Daemon start success! 即表示服务就绪。默认监听 0.0.0.0:1025。

⚠ 老版本 MindIE 共存

若曾安装 /usr/local/Ascend/mindie 老版本，请改名避免库冲突： mv /usr/local/Ascend/mindie /usr/local/Ascend/mindie-bak。

第五步：发送请求

新开终端，使用 curl 验证：

curl -H "Content-Type: application/json" \
     -X POST \
     -d '{"prompt":"My name is Olivier and I","max_tokens":16}' \
     http://127.0.0.1:1025/generate

正常响应：

{"text":["My name is Olivier and I am 25 years old. I am a French student"]}

同一服务还可以走 OpenAI 风格接口：

curl -H "Content-Type: application/json" -X POST \
  -d '{
    "model": "qwen2-7b",
    "messages": [{"role":"user","content":"用三句话介绍昇腾"}],
    "max_tokens": 128
  }' \
  http://127.0.0.1:1025/v1/chat/completions

第六步（可选）：精度 & 性能测试

MindIE-LLM 推荐使用 AISBench。 容器中已预装，可通过 pip show ais_bench_benchmark 找到位置。 流程概览：

  1. 下载数据集（如 gsm8k）， 放入 ais_bench/datasets/。
  2. 修改 ais_bench/benchmark/configs/models/vllm_api/vllm_api_stream_chat.py， 设置 host_ip=127.0.0.1、host_port=1025、model="qwen2-7b"。
  3. 跑精度：
    ais_bench --models vllm_api_stream_chat \
  --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt --debug
  4. 跑性能：在上述命令后追加 --mode perf。

关键指标：TTFT（首 token 时延）、TPOT（每 token 输出时延）、 Request Throughput、Output Token Throughput。

清理与重启

# 停止服务（守护进程模式下用 Ctrl-C 或调用 stopService API）
curl -X GET http://127.0.0.1:1025/stopService

# 切换用户后清理共享内存（避免权限错误）
rm -f /dev/shm/*
