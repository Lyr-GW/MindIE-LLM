Context Parallel（上下文并行）

把长 prompt 的 prefill 计算沿序列维度切到多卡并行， 用 ring 通信传递 KV 完成全局 attention。是「降低长上下文首 token 时延」的关键武器。

问题：长 prompt 的 prefill 时间

对一个 128k 上下文的 prompt，attention 矩阵的复杂度是 O(L²) — 单卡跑 prefill 可能要分钟级。 此时整批请求都被卡死等待。

原理（类 Ring-Attention）

   把 sequence 切成 N 份，每张卡持一段 (q_i, k_i, v_i)
       │
       ▼   step 1：本地算 q_i @ k_i^T
       │   step 2：以 ring 方式向左 / 右传 k_j、v_j
       │   step 3：累加 partial attention，分块 softmax 修正
       ▼
   全局 attention = sum over all blocks (经修正)

实现采用 Flash-Attention 2 风格分块 + ring 通信。每张卡仅持有 1/N 的 KV， 最终通过算子内的 log-sum-exp 修正得到正确结果。

配置

"ModelConfig": [{
  "modelName":       "DeepSeek-R1_w8a8",
  "modelWeightPath": "/data/weights/DeepSeek-R1_w8a8",
  "worldSize":       16,
  "dp":  1,
  "cp":  2,    // 把 sequence 切成 2 份
  "sp":  8,    // 必须 = tp
  "tp":  8,
  "moe_ep": 16,
  "moe_tp": 1
}]

当前 cp 取值仅支持 1（关）或 2（开）。

必须同时开启 SP

CP 在切分上下文的同时，需要把 KV 也切到多卡 — 由 SP（序列并行） 负责。规则：

  • dp = 1（CP 与 DP 互斥）；
  • sp = tp；
  • cp × dp × tp = worldSize。

已知限制

  • Atlas 800I A2 / A3 支持。
  • 仅 DeepSeek-R1 (W8A8 / W4A8)、DeepSeek-V3 (W4A8)、DeepSeek-V3.1 (W4A8) 支持。
  • 不支持 BF16。
  • PD 分离时仅在 P 节点开启 CP。
  • 支持与 MTP=1（PD 混部下）/ 异步调度 / Prefix Cache 叠加。

收益

  • 128k 长 prefill TTFT 降低近 N 倍（N = cp 倍数）。
  • 显存压力按 1/N 降低，单卡可装更长上下文。
