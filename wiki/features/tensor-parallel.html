Tensor Parallel（张量并行）

把模型权重沿维度切分到多张卡，每张卡只算一部分；通过 AllReduce 把结果合起来。 是单实例多卡推理 70B 这类大模型的必经之路。

为什么需要 TP

一个 70B 模型 fp16 约 140 GB，单张 NPU 装不下；即便装得下，单卡算力也吃不动 prompt 长度 8k 的 prefill。把权重在 head / hidden 维度切开，各卡并行算，是最自然的方案。

原理（Megatron 风格）

对 Linear y = W·x 的两种切法：

  • Column-Parallel：W 按列切 → 各卡输出 y 的不同列 → 不需要立刻合并。
  • Row-Parallel：W 按行切 → 各卡需要相同的 x → 算完 partial sum → 一次 AllReduce 合成 y。

典型结构 ColumnLinear → activation → RowLinear 把两次 matmul 之间的通信省到 只剩 1 次 AllReduce。Attention 中的 head 切分逻辑类似。

   x ──→ ColumnLinear (W₁ 按列切)  →  partial activations
                                            │
                                       activation
                                            │
   ──→ RowLinear (W₂ 按行切) → partial sums ──AllReduce── y

在 MindIE-LLM 中的实现

Python 层：mindie_llm/runtime/layers/linear/ 提供 ColumnParallelLinear / RowParallelLinear；通信组通过 mindie_llm/distributed/ 创建（HCCL）。

配置

"ModelConfig": [{
  "modelName":       "qwen2-72b",
  "modelWeightPath": "/weights/qwen2-72b",
  "worldSize":       8,        // 所用卡数
  "tp":              8         // TP = 8
}]

worldSize 与 tp 的关系：单实例下两者通常相等。配合 DP / EP 时按 tp × dp × ... = worldSize 计算。

DeepSeek 专用：local TP 切分

对 DeepSeek-V3 / R1 / V3.1，可对部分矩阵做更细粒度切分：

  • lm_head_local_tp：LmHead 矩阵的 TP 切分数，减少计算时间。
  • o_proj_local_tp：Attention O 矩阵的 TP 切分数，PD 分离的低时延场景下减少 decode 时延。
"models": {
  "deepseekv2": {
    "parallel_options": {
      "lm_head_local_tp": 4,
      "o_proj_local_tp":  2
    }
  }
}
⚠ 互斥

当 tp > 1 时，不支持 与 o_proj_local_tp 同时开启；也不建议 与 lm_head_local_tp 同时开启。

权衡

  • TP 越大：单卡显存压力越小，但 AllReduce 通信占比越高、吞吐反而可能下降。
  • NPU 内卡间带宽优先（同一 superpod > 同机内 > 跨机），尽量把 TP 限制在带宽好的范围。
  • 常见组合：单机 8 卡 → TP=8；超节点 144 卡 → TP=8 + EP=18（举例）。

已知限制

  • Atlas 800I A2 / A3 支持。
  • DeepSeek-V3/R1：local TP 切分有专门约束，详见上文。
