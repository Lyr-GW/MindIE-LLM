MTP — Multi-Token Prediction

DeepSeek-V3 提出的「单步多 token」并行解码方法。模型本身被训练为 同时预测多个未来 token，推理时一次 forward 就能输出 K 个 token，吞吐显著提升。

与一般投机解码的差异

  • 一般投机解码：用独立 draft 模型或主模型自身（lookahead）生成候选 token， 再回主模型校验。
  • MTP：模型自身就有一个 MTP head，专门输出未来若干 token； 这些预测在训练时就被监督。

因此 MTP 不需要额外的 draft 模型，权重里自带 MTP 模块，命中率更高更稳定。

配置

"ModelConfig": [{
  "modelName":       "DeepSeek-R1_w8a8",
  "modelWeightPath": "/data/weights/DeepSeek-R1_w8a8",
  "worldSize":       8,
  "plugin_params":   "{\"plugin_type\":\"mtp\",\"num_speculative_tokens\":1}"
}]

num_speculative_tokens 取值 1 或 2：

  • 低时延场景：1 或 2，加速解码同时保持稳定。
  • 高吞吐场景：建议 ≤ 1，避免校验失败率过高反而拖慢。

在 Python 框架中的实现

mindie_llm/text_generator/plugins/mtp/ 实现 MTP head 调用与 多 token 校验逻辑。模型 forward 输出主 token + N 个 MTP 预测；sampler 负责校验 （第一个不一致的位置后丢弃，已通过的保留）。

支持叠加

  • Prefix Cache 与 KV Cache 池化
  • 异步调度
  • KV Cache Int8
  • Function Call
  • 思考解析
  • PD 分离（P / D 节点需同时配置）
  • 部分场景支持 CP + SP （PD 混部仅 num=1，大 EP + CP/SP 仅 P 节点开启）

已知限制

  • Atlas 800I A2 / A3 支持。
  • 仅 DeepSeek-R1、DeepSeek-V3 的 W8A8 / KV Int8 模型支持；W4A8 也支持。
  • 不能与 并行解码、Multi-LoRA、 SplitFuse 同开。
  • 不支持 n / best_of / use_beam_search / logprobs 等多序列后处理。
  • 惩罚后处理仅支持 repetition_penalty。

收益

  • DeepSeek-R1 上 num=1 时吞吐提升 30–60%。
  • num=2 时吞吐再提升 10–20%（需配业务评估校验通过率）。
