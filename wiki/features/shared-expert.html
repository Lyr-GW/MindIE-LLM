共享专家外置 / 内置 / 混置

MoE 模型常有「共享专家」（每个 token 都过）。MindIE-LLM 提供三种部署方式 把它放在不同位置，平衡通信、算力与负载均衡效果。

三种部署形态

共享专家外置（推荐）

把共享专家独立部署到专门的前几张 NPU，与路由专家 / 冗余专家分离。

计算流程：dispatch → 同时计算共享专家 + 路由专家 → combine
  • 共享专家所在 NPU 不参与 AllToAll，专心做密集计算。
  • 路由专家所在 NPU 专心做稀疏路由，负载均衡更纯粹。
  • 整体 TPOT 显著改善。

共享专家内置

共享专家与路由 / 冗余专家共住一张 NPU。

计算流程：共享专家 matmul → dispatch → 路由专家 → combine → 共享 + 路由结果相加

无额外卡需求，但共享专家会与路由专家争抢算力，对 EPLB 干扰大。

共享专家混置

把共享专家当作普通路由专家纳入负载均衡考量。

计算流程：dispatch → 同时计算共享专家 + 路由专家 → combine
  • EPLB 算法把它视为一个高频专家，自动复制到多卡。
  • 对 Atlas 800I A2 / A3 都支持。

三者对比

外置内置混置
额外卡需要不需要不需要
是否参与 EPLB否否是
支持平台800I A3 144 卡所有800I A2 / A3
配合 EPLB性能更优—性能更优

如何开启

（推荐）外置 + EPLB

先按 EPLB 步骤生成 expert_map.json。

"models": {
  "deepseekv2": {
    "ep_level": 2,
    "eplb": {
      "level": 1,
      "expert_map_file": "/path/to/expert_map.json"
    }
  }
}

外置（仅 800I A3 144 卡）

"models": {
  "deepseekv2": {
    "ep_level": 2,
    "num_dangling_shared_experts": 32   // 多少个共享专家被外置
  }
}

仅混置

"models": {
  "deepseekv2": {
    "mix_shared_routing": true
  }
}

已知限制

  • 仅支持 DeepSeek-V3 / R1。
  • 「外置」仅支持 Atlas 800I A3 超节点 144 卡场景。
  • 「混置」同时支持 800I A2 / A3。
  • W4A8 + 共享专家外置时，需要使用共享专家本身也是 W4A8 的特殊权重。
