Sequence Parallel（序列并行）

把 KV Cache 沿序列维度切分到多卡，每张卡只存自己的一段 KV — 是 「长上下文 decode」时不让 KV 撑死的核心手段。

问题：长上下文的 KV 也太大

即使开启 CP 解决了 prefill，decode 阶段的 KV Cache 仍持 整个序列；128k 序列下 KV 体积非常可观。SP 把 KV Cache 沿 seq 维切分，每个 sp_rank 只存 L / sp 段。

   sp = 4 时 KV Cache 分布：
     rank 0:  KV[ 0   :  L/4 ]
     rank 1:  KV[ L/4 : 2L/4 ]
     rank 2:  KV[ 2L/4: 3L/4 ]
     rank 3:  KV[ 3L/4: L   ]

   decode 计算 q @ K^T:
     每 rank 算 q @ K_local^T  → AllGather 合并 → softmax → 加权 V_local → AllReduce

配置

"ModelConfig": [{
  "modelName":       "DeepSeek-R1_w8a8",
  "modelWeightPath": "/data/weights/DeepSeek-R1_w8a8",
  "worldSize":       16,
  "dp":  2,
  "sp":  8,    // 必须 = tp
  "tp":  8,
  "moe_ep": 16,
  "moe_tp": 1
}]

规则：sp = tp。组合自由：

  • DP × TP × SP（不开 CP）：dp × tp = worldSize
  • CP × TP × SP（开 CP）：cp × tp = worldSize 且 dp = 1

已知限制

  • Atlas 800I A2 / A3 支持。
  • 仅 DeepSeek-R1 (W8A8 / W4A8)、DeepSeek-V3 (W4A8)、DeepSeek-V3.1 (W4A8) 支持。
  • 不支持 BF16。
  • PD 分离时仅 P 节点开启 SP。
  • 与 MTP = 1（PD 混部）/ MTP（PD 分离）/ 异步调度 / Prefix Cache 叠加 OK。

收益

  • KV 显存按 1/sp 降；128k 上下文场景可避免 OOM。
  • decode 单步多一次 AllGather + AllReduce，时延略增；但能跑得动是首要前提。

叠加方案

SP 与 CP 是「长 prefill + 长 decode」的黄金搭档， DeepSeek-R1 长上下文场景的标准配置就是 cp=2 + sp=tp=8 + dp=1。
