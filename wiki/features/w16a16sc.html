W16A16SC 浮点稀疏压缩

W8A8SC 是「INT8 稀疏量化」，本特性是「FP16 浮点稀疏压缩」 — 不做位宽降低，只做稀疏化和存储压缩。适用于精度敏感、又想从带宽要性能的场景。

与 W8A8SC 的差异

W8A8SCW16A16SC
权重位宽int8fp16（保留精度）
激活位宽int8fp16
是否稀疏是是
是否压缩存储是是
是否需要反量化算子是否
支持平台Atlas 300I DuoAtlas 300I Duo
适用模型Qwen3-8B/14B/32BQwen3-32B

为什么浮点稀疏

稀疏化的本质是「少算 + 少存」。相比 INT8：

  • 不需要反量化算子 — 节省一次 op 与 scale 张量；
  • 精度等于原 fp16（仅有稀疏化引入的近似误差）；
  • 缺点是单元素仍占 16 bit，单纯压缩比不如 W8A8SC。

权重描述

稀疏阶段：

{
  "model_quant_type": "W16A16S",
  "model.embed_tokens.weight": "FLOAT",
  "model.layers.0.self_attn.q_proj.weight": "W16A16S",
  "model.layers.0.self_attn.k_proj.weight": "W16A16S",
  "model.layers.0.self_attn.v_proj.weight": "W16A16S",
  "model.layers.0.self_attn.o_proj.weight": "W16A16S"
}

压缩阶段（按 TP 数切分多份目录）：

{
  "model_quant_type": "W16A16SC",
  "transformer.h.0.attn.c_attn.weight": "W16A16SC",
  "transformer.h.0.attn.c_attn.index":  "W16A16SC",
  "transformer.h.0.attn.c_attn.info":   "W16A16SC",
  "transformer.h.0.attn.c_attn.weight.outdim": 2560,    // 用于还原输出维度
  "transformer.h.0.attn.c_proj.weight.outdim": 5120
}
张量weightquant_biasindex
dtypeint8fp32int8
shape[x] 由压缩率决定[n][y] 非零索引

注意：虽然 weight dtype 标为 int8，本质是「压缩存储格式」 — 解压后参与计算的值仍是 fp16。

生成 + 压缩 + 推理

# 1. 浮点稀疏
msmodelslim quant \
  --model_path /home/Qwen3-32B \
  --save_path  /home/Qwen3-32B-W16A16S \
  --device     npu \
  --model_type Qwen3-32B \
  --quant_type w16a16s \
  --trust_remote_code True

# 2. 切分 + 压缩
torchrun --nproc_per_node 4 \
  -m examples.convert.model_slim.sparse_compressor \
  --model_path /home/Qwen3-32B-W16A16S \
  --save_directory /home/Qwen3-32B-W16A16SC

# 3. 推理
cd ${ATB_SPEED_HOME_PATH}
torchrun --nproc_per_node 4 -m examples.run_pa --model_path /home/Qwen3-32B-W16A16SC

收益

  • 权重体积约 fp16 的 50–60%（视稀疏率）。
  • matmul 走稀疏算子，吞吐提升 1.2–1.4×。
  • 精度几乎无损（< 0.3 pp）。

已知限制

  • 仅 Atlas 300I Duo 推理卡支持。
  • 仅支持 Qwen3-32B。
  • 需要按 TP 数预切分；TP 改变需重新压缩。
