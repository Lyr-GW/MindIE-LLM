MLA — Multi-head Latent Attention

DeepSeek 系列首推的注意力变体：用低秩 KV 联合压缩 消除 KV Cache 瓶颈。MindIE-LLM 支持 单 Cache MLA — 把 head 维度压到 1，访存极致友好。

为什么需要 MLA

传统 MHA 的 KV Cache 大小：

kv_cache_size = 2 (K, V) × n_heads × head_dim × seq_len × 2 bytes(fp16)

对一个 128k 上下文的 70B 模型，单序列 KV ~30 GB。带宽和容量都吃不消。

MLA 做了关键观察：在 inference 阶段我们只关心 K 和 V 在计算 attention 时的线性投影， 而不是它们各自的全维度。它把 K、V 共同压缩成一个低秩 latent c_kv， 存储 latent 而不是 K/V 本身。

原理（精简）

// 训练 / 离线：
W_DKV : 把 hidden 投到 latent 维 (低秩)
W_UK  : 从 latent 解出 K
W_UV  : 从 latent 解出 V

// 推理时：
c_kv = x @ W_DKV          // 低秩缩减，存到 KV Cache（小！）
k    = c_kv @ W_UK
v    = c_kv @ W_UV
attn = softmax(q @ k^T) @ v

对 RoPE 友好的位置编码段单独保留（见 FA3 量化），即所谓 k_pe 部分。

单 Cache MLA

MindIE-LLM 实现的「单 Cache MLA」把多头折叠成等效 1 个 head：所有 head 共享同一份压缩 latent， 代价是把 head 内的差异交给后续矩阵乘吸收。带来：

  • 显存：相比 MHA 压缩 96.5%（DeepSeek-V2 实测）；
  • 访存：单 cache、单连续矩阵，PagedAttention 取数极简单；
  • 算力：从 N×head 矩阵乘转化为 1×大矩阵，更易组 batch。

在 MindIE-LLM 中的实现

  • Python 层：mindie_llm/runtime/layers/attention/ 中的 MLA 实现， 与 ATB Models 中的 DeepSeek-V2 适配层协作。
  • 权重侧：标准 DeepSeek-V2/V3 权重即附带 MLA 投影矩阵，无需额外格式。
  • KV 池：对 MLA 的 c_kv 走专用 layout，在 src/block_manager/ 中通过 blockSize 自适应。

如何开启

没有开关 — 模型本身用 MLA（DeepSeek-V2/V3/R1、Qwen3 部分版本）， MindIE-LLM 自动走 MLA 路径。

cd ${ATB_SPEED_HOME_PATH}
bash examples/models/deepseekv2/run_pa.sh /weights/DeepSeek-V2-Chat

叠加方案

  • FA3 量化：MLA + KV 量化的最佳搭档。
  • Context Parallel：MLA 节省的显存让长上下文更可行。
  • MTP：DeepSeek-V3 自带 MTP head，与 MLA 共生。
