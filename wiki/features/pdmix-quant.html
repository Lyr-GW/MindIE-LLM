PDMIX 量化

在同一个模型里，prefill 与 decode 使用不同的量化方案： prefill 用 W8A8 Dynamic（per-token，保精度）、decode 用 W8A8 Static（per-tensor，保性能）。 是「精度 + 吞吐」的工程平衡点。

为什么 P / D 应该分开

  • Prefill：一次性吃完整 prompt，激活分布跨度大（不同 token 类型量纲不同）。 per-token 量化能逐 token 选最合适的 scale，精度好。
  • Decode：一次只处理 1 个 token，访存比远低于 prefill。 per-tensor 静态量化省去逐 token 计算 scale 的开销，吞吐更高。

把两个阶段当成两种工作负载分别选量化策略，就是 PDMIX 的核心思想。

两种量化的对比

W8A8 Dynamic (Per-token)W8A8 Static (Per-tensor)
scale 粒度每 token 一个整 tensor 一个
计算开销每步多一次 reduce固定，最小
精度更高（动态适配）稍低
典型阶段PrefillDecode

权重描述

{
  "model.layers.0.self_attn.q_proj.weight":        "W8A8_MIX",
  "model.layers.0.self_attn.q_proj.input_scale":   "W8A8_MIX",   // static 的 scale
  "model.layers.0.self_attn.q_proj.input_offset":  "W8A8_MIX",
  "model.layers.0.self_attn.q_proj.deq_scale":     "W8A8_MIX",
  "model.layers.0.self_attn.q_proj.weight_scale":  "W8A8_MIX",   // 反量化用
  "model.layers.0.self_attn.q_proj.weight_offset": "W8A8_MIX",
  "model.layers.0.self_attn.q_proj.quant_bias":    "W8A8_MIX"
}

张量布局：

张量weightquant_biasinput_scaleweight_scale
dtypeint8int32bf16bf16
shape[n,k][n][1][n,1]

推理时切换

调度器维护每个序列处于 prefill 还是 decode 状态：

   if (seq.stage == PREFILL):
       use perTokenQuantPath()   // 实时算 input_scale
   else:                          // DECODE
       use perTensorQuantPath()  // 用权重里固定的 input_scale

在 LayerwiseMixin 中根据 stage 切换 op 路径。 ATB 算子层有「双套」kernel：动态路径每步重新归一化，静态路径直接 INT8 矩阵乘。

如何开启

msmodelslim quant \
  --model_path /home/Qwen3-14B \
  --save_path  /home/Qwen3-14B-W8A8PDMIX \
  --device     npu \
  --model_type Qwen3-14B \
  --quant_type w8a8 \
  --trust_remote_code True
# 默认实现就是 PDMIX 形态

收益

  • 相比纯 W8A8 Static：CMMLU 等评测精度恢复 1–2 pp。
  • 相比纯 W8A8 Dynamic：decode 阶段吞吐提升 10–20%。
  • 是 Qwen3 / DeepSeek 等模型的「默认推荐量化方案」。

兼容性

  • 需要 PDMIX 形态的量化权重（msModelSlim 默认输出即是）。
  • 配合 Anti-Outlier 效果最佳。
  • 与 Multi-LoRA 不兼容。
