Expert Parallel（专家并行）

把 MoE 模型的不同专家分布到不同 NPU 上，实现「专家级」并行。 MindIE-LLM 提供 AllGather 与 AllToAll + 通算融合两种实现，按场景择优。

为什么 MoE 要 EP

MoE 模型一层有几十甚至几百个专家，所有专家放一卡显存装不下；放到不同卡又需要把 token 路由 到对应专家所在的卡 — 这就是 EP 的核心。

两种实现（ep_level）

ep_level = 1：基于 AllGather

  • 每张卡先 AllGather 所有专家的输入 hidden_states；
  • 本地按 routing 决定哪些 token 由本地专家计算；
  • 计算完毕后丢弃非本地结果，再 AllReduce 合并。

优点：实现简单、对通信拓扑要求低； 缺点：通信量大，长序列下显存压力大。

专属优化：enable_init_routing_cutoff + topk_scaling_factor 允许 topk 截断，丢弃 hidden_states 末段无效数据，省显存。

ep_level = 2：基于 AllToAll + 通算融合

  • 使用 AllToAll：每张卡把需要别的专家计算的 token 一次性发送到对应卡；
  • 每张卡只算自己负责的专家；
  • 结果通过 AllToAll 反向回收。

优点：通信量与 token 数成正比，算力 / 通信效率都最优； 缺点：双机部署时必须经交换机，否则启动失败。

专属优化：alltoall_ep_buffer_scale_factors 按序列长度分级控制通信 buffer 大小， 避免短序列浪费、长序列 OOM。

配置示例

ep_level = 2（推荐 DeepSeek-V3 / R1）：

"ModelConfig": [{
  "modelName":       "DeepSeek-R1_w8a8",
  "modelWeightPath": "/data/weights/DeepSeek-R1_w8a8",
  "worldSize":       8,
  "moe_ep":          8,
  "models": {
    "deepseekv2": {
      "ep_level": 2,
      "alltoall_ep_buffer_scale_factors": [
        [1048576, 1.32], [524288, 1.4], [262144, 1.53],
        [131072, 1.8], [32768, 3.0], [8192, 5.2], [0, 8.0]
      ]
    }
  }
}]

ep_level = 1（长序列、跨拓扑场景）：

"models": {
  "deepseekv2": {
    "ep_level": 1,
    "enable_init_routing_cutoff": true,
    "topk_scaling_factor": 0.25
  }
}

Grouped MatMul 融合算子

当 EP 数 > 32 时，DeepSeek-V3 / R1 自动启用 Grouped MatMul：把同一卡上多个专家的 matmul 合并成一次大算子，降低 kernel launch 开销。

在 MindIE-LLM 中的实现

Python 层 mindie_llm/runtime/layers/fused_moe/ 与 mindie_llm/distributed/ 协作。distribute 层负责创建 EP 通信组（HCCL），fused_moe 算子负责 routing、permute、grouped matmul、reduce。

叠加方案

  • + EPLB 负载均衡：处理热点专家。
  • + 共享专家外置：把高频共享专家独立部署。
  • + DP：多实例稀疏推理。

已知限制

  • 仅 DeepSeek-V2 / V3 / R1 支持。
  • ep_level = 2 双机必须经交换机。
  • 当 EP > 32 自动 Grouped MatMul，可显著提升性能。
