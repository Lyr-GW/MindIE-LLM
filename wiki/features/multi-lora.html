Multi-LoRA

基于一个基础大模型，同时托管多个 LoRA Adapter，请求级动态切换。 把 N 个微调模型「合住」一份基础权重，是 SaaS / 多租户 LLM 服务的核心特性。

什么是 LoRA

LoRA（Low-Rank Adaptation）通过把权重矩阵的微调项分解为两个小矩阵的乘积来减少训练参数：

原始: y = W · x      (W: [d_out, d_in])
微调: W' = W + B·A    (B: [d_out, r], A: [r, d_in], r ≪ min(d_out, d_in))

仅 B 和 A 参与训练（参数量约为 2 r (d_out+d_in)），训练成本是全量微调的 ~1%。 推理时 Adapter 可合并到 W（合并后跟普通模型一样），也可动态加权 （灵活切换不同 LoRA）。

为什么 Multi-LoRA

  • 共享显存：基础权重只装一次（70B 一份就 ~140 GB），Adapter 各自约几十 MB。
  • 请求级切换：每次请求带 lora_id，引擎查表挑权重， 不同请求可在同一 batch 中运行。
  • 动态加载 / 卸载：通过管理端 API 在运行时增删 Adapter， 不必重启服务。

Adapter 权重格式

adapter1/
├─ adapter_config.json       # r、lora_alpha、target_modules
└─ adapter_model.safetensors # base_model.model.<layer>.lora_A.weight / lora_B.weight

键名规则：在基础模型张量名前加 base_model.model. 前缀、后加 .lora_A.weight / .lora_B.weight。例：

基础: model.layers.9.self_attn.v_proj.weight
LoRA: base_model.model.model.layers.9.self_attn.v_proj.lora_A.weight
      base_model.model.model.layers.9.self_attn.v_proj.lora_B.weight

如何开启

服务化配置

"ModelDeployConfig": {
  "ModelConfig": [{
    "modelName": "llama3.1-70b",
    "modelWeightPath": "/data/weights/llama3.1-70b-safetensors",
    "worldSize": 8
  }],
  "maxLoras": 4,            // 同时驻留显存的 Adapter 数上限
  "maxLoraRank": 296,       // 支持 Adapter 的最大 r
  "LoraModules": [{
    "name": "adapter1",
    "path": "/data/lora/llama3.1-70b-lora-1",
    "baseModelName": "llama3.1-70b"
  }]
}

运行时管理

# 加载新 Adapter（管理端口）
curl -X POST http://127.0.0.2:1026/v1/load_lora_adapter \
  -H "Content-Type: application/json" \
  -d '{"lora_name":"adapter2","lora_path":"/data/lora/llama3.1-70b-lora-2"}'

# 卸载
curl -X POST 127.0.0.2:1026/v1/unload_lora_adapter \
  -d '{"lora_name":"adapter2"}'

# 查看可用模型 / Adapter
curl http://127.0.0.1:1025/v1/models

请求侧

把 "model" 字段设为基础模型名 → 不走 LoRA；设为 Adapter 名 → 启用对应 LoRA：

curl http://127.0.0.1:1025/generate -X POST \
  -d '{"model":"adapter1","prompt":"Q: ...\nA:","max_tokens":32}'

引擎内部

对应 src/engine/lora_manager.cpp + Python 侧 mindie_llm/runtime/lora/。流程：

  1. 启动时把基础权重 + 已声明的全部 Adapter 加载到 NPU；
  2. 调度器发现请求带 lora_id，把 ID 注入 SequenceGroup metadata；
  3. 组 batch 时不区分 LoRA — 同 batch 可有多个不同 LoRA 请求；
  4. Linear 层算 forward 时通过 LoraOpsMixin 把每个请求的 LoRA Δ 一并计算并叠加： y = (W·x) + (Bᵢ · (Aᵢ · x))；
  5. Prefix Cache 哈希中加入 extraHash = lora_id，避免不同 LoRA 错配 KV。

限制

  • Atlas 800I A2 / A3、Atlas 300I Duo 支持。
  • Adapter 数量受显存上限约束，建议 ≤ 10。
  • 仅 ATB Models Python 组图模式支持动态加 / 卸载。
  • 当前版本与量化 / PD 分离 / 并行解码 / SplitFuse / MTP / 异步调度 / Micro Batch / Prefix Cache 不能同开。
  • 仅支持 Qwen2.5-7B/14B/32B/72B、Qwen3-32B、LLaMA3.1-8B/70B、Qwen2-72B。
  • LoRA 名称 ≤ 256 字符；线性层支持 LoRA、其它层不行。
  • 仅 vLLM / TGI / OpenAI 兼容接口可指定 LoRA。
