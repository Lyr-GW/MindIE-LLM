EPLB — Expert Parallelism Load Balancer

MoE 模型的热点专家会让所在 NPU 负载爆炸、空闲专家所在 NPU 算力浪费。 EPLB 通过统计 → 冗余复制 → 路由再平衡显著降低卡间不均衡度。

问题：专家分布不均

MoE 的 router 由训练数据决定，部分专家被频繁选中（流量集中），部分极少被路由。 当 EP 把不同专家分到不同卡：

   NPU 0:  [Expert 5]    ← 流量 80%（热点）   ← 算力打满 / 通信拥塞
   NPU 1:  [Expert 1]    ← 流量 5%
   NPU 2:  [Expert 2]    ← 流量 10%
   NPU 3:  [Expert 3]    ← 流量 5%
                         平均利用率仅 ~25%

两种模式

  • 静态冗余负载均衡（推荐生产）：在路由专家所在 NPU 上，额外复制 热点专家。原本 80% 流量集中到 NPU 0，复制后可分摊到多张卡。每卡多部署 1 个 冗余专家约占 2.4 GB 显存。
  • 强制负载均衡（仅理论上限）：用「假 topk」让所有专家 平均分配 token；改变了模型路由结果，不能用于正式业务，仅作性能上限测试。

使用流程

   ① 关闭 EPLB 跑业务，开 MINDIE_ENABLE_EXPERT_HOTPOT_GATHER=1
   ② 各卡导出 .csv 专家热点信息
   ③ 收集到同一目录（或共享盘）
   ④ 用 msit elb 工具生成「冗余专家部署表」
   ⑤ 在 config.json 开启 EPLB 并指向部署表

步骤 ①：采集热点

# 在各卡的环境变量中添加（mindie_env.json）
export MINDIE_ENABLE_EXPERT_HOTPOT_GATHER=1
export MINDIE_EXPERT_HOTPOT_DUMP_PATH=/共享盘/eplb_dump/
mindie_llm_server   # 跑一段你的真实业务，再关闭

每卡输出一个矩阵（layer 数 × 单卡专家数），每 8 token 追加一次。

步骤 ②：生成部署表

git clone https://gitcode.com/Ascend/msit.git
cd msit/msit && pip install . && msit install elb

# 8 机 64 卡，DeepSeek-R1 典型参数
msit elb -icp /共享盘/eplb_dump \
         -o   /共享盘/expert_map.json \
         -nre 64 -nd 8 -nn 64 \
         -al  5     # speculative-moe level-2 混置算法
         -dt  a2

PD 分离场景下分别为 P / D 端跑一次。

步骤 ③：开启 EPLB

编辑 {ATB安装路径}/atb-models/atb_llm/conf/config.json：

"models": {
  "deepseekv2": {
    "eplb": {
      "level": 1,                              // 0 关 / 1 静态冗余 / 3 强制
      "expert_map_file": "/共享盘/expert_map.json"
    }
  }
}

已知限制

  • Atlas 800I A2 / A3 支持。
  • DeepSeek R1 / V3、Qwen-MoE 支持。
  • 仅在 ep_level=2（AllToAll）场景下有效。
  • PD 分离两端调度策略不同，需独立配置。
  • 每卡多 1 个冗余专家，约多占 2.4 GB 显存。
  • 强制负载均衡仅作上限测试，不可上线。

收益

  • 典型场景下卡间负载差从 4–6× 降到 1.2–1.5×。
  • 整体吞吐提升 15–35%，TPOT 显著改善。
